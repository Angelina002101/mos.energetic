# Сайт энергетических услуг — готовый комплект для GitHub и Vercel

## Загрузка

1. Распакуйте архив на компьютере.
2. Откройте распакованную папку: внутри сразу должны быть index.html, package.json, vercel.json и папки api, assets, scripts, tests.
3. В GitHub откройте репозиторий → Add file → Upload files. Перетащите ВСЁ содержимое распакованной папки, сохраняя папки. Сам ZIP загружать не нужно. Порядок файлов не важен.
4. Commit changes. Убедитесь, что api/contact.js и scripts/build.mjs находятся на своих местах. Если ранее внесли реквизиты в privacy.html и consent.html, перенесите их в эти файлы до загрузки: архив не содержит ваших последующих изменений на GitHub.
5. В Vercel импортируйте репозиторий. Если он уже подключён — дождитесь новой сборки или нажмите Redeploy.

## Настройки Vercel ДЛЯ ЭТОЙ ВЕРСИИ

| Поле | Значение |
| --- | --- |
| Framework Preset | Other |
| Root Directory | Корень репозитория — где package.json и vercel.json |
| Build Command | npm run build |
| Output Directory | public |
| Install Command | Стандартное значение; внешних зависимостей нет |
| Node.js | 22.x (задано в package.json) |

Build Command и Output Directory уже записаны в vercel.json. Если в интерфейсе остались старые ручные значения, установите значения из таблицы. Не выбирайте api или public как Root Directory.

Если вы загрузили весь комплект внутрь папки репозитория, Root Directory должна указывать на эту папку — там, где package.json и vercel.json.

Сборка сама создаёт public/ с HTML, CSS, браузерным JS и изображениями. Не создавайте её вручную. Серверный код api/contact.js остаётся в корне проекта, за пределами public. Скрипт сборки проверяет обязательные файлы, чтобы потерянная при загрузке папка api дала понятную ошибку.

## Настройка Telegram — обязательна для формы

Vercel → Settings → Environment Variables:

| Name | Value |
| --- | --- |
| TELEGRAM_BOT_TOKEN | Токен вашего Telegram-бота из переписки |
| TELEGRAM_CHAT_ID | 760621513 |

Добавьте переменные для Production и, при необходимости, Preview. Затем выполните Redeploy. Токен не включён в архив, HTML или браузерный JavaScript. В GitHub его добавлять не нужно. .env.example содержит только названия переменных и пример без токена.

В личном чате с ботом нажмите Start или отправьте /start, если ещё не делали этого.

## Проверка после публикации

1. Откройте сайт, затем добавьте /api/contact в адресной строке после домена.
2. При настроенных переменных вернётся JSON с question и challenge. При ненастроенных — JSON с сообщением о настройке формы и статусом 503. Ошибка 404 или HTML вместо JSON означает, что API-функция не развернулась: проверьте Root Directory и папку api.
3. Вернитесь на сайт, заполните заявку, решите пример, отметьте согласие и отправьте. Сообщение должно появиться в вашем Telegram-чате.
4. Если бот не доставляет заявки: проверьте токен, chat ID, доступ бота к чату и запуск /start. После исправления переменных сделайте Redeploy.

## Файлы

- index.html — страница, можно открыть на компьютере для просмотра;
- styles.css — адаптивное оформление;
- app.js — браузерная логика формы и обновление проверки от спама;
- assets/hero.webp, assets/substation.webp — сгенерированные иллюстрации;
- assets/favicon.svg — значок сайта;
- api/contact.js — серверная отправка в Telegram;
- scripts/build.mjs — сборка и проверка обязательных файлов;
- tests/contact.test.mjs — автоматические проверки серверной логики;
- package.json, vercel.json — настройки сборки и Vercel;
- privacy.html, consent.html — тексты обработки данных;
- .gitignore, .env.example — вспомогательные файлы без секретов.

## Что проверено

- Синтаксис JavaScript и настройки JSON.
- Сборка командой npm run build и состав public/.
- Пути к HTML, изображениям и якорям.
- 20 сценариев серверной логики внутри одной группы (21 успешный тест по счётчику Node): успешная имитация отправки, ошибки Telegram и сети, подпись и срок проверки, неверные данные, повторная заявка, Origin и отсутствие настроек.
- Архив не содержит токена, локальных файлов предпросмотра или лишней внешней папки.

Тесты не отправляют настоящие сообщения. Развёртывание в вашем аккаунте Vercel и реальная доставка в Telegram здесь не выполнялись. Это нужно проверить после публикации. Локальная сборка проверена на Node 24; в Vercel проект использует Node 22, код использует поддерживаемые им API.

## Защита формы

Есть арифметическая проверка с серверной подписью и сроком 10 минут, скрытое поле-ловушка, проверка обязательного согласия, Origin и ограничение повторов с одного телефона на одном экземпляре функции. Это базовая защита, а не распределённая система против массового спама. Посетитель может обновить пример вручную; устаревающая проверка обновляется при продолжении заполнения.

Сайт не ведёт отдельную базу заявок и не сохраняет их в браузере; сообщения остаются в рабочем чате Telegram. Успех показывается только после подтверждения API Telegram.
